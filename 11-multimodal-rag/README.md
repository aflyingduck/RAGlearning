# 11 — Multimodal RAG

Every prior project retrieved text. This one adds two images —
`status-ring-legend.png` (a color-coded legend of what each status ring
color means) and `hub-mesh-topology.png` (a two-hub network diagram) —
generated by `generate_images.py`, whose content exists **only** as
pixels, not duplicated anywhere as a caption or alt-text. Voyage's
multimodal embedding model (`voyage-multimodal-3`) embeds raw images and
text into a shared space, so a query can retrieve an image based on what's
actually drawn in it.

```
cd 11-multimodal-rag
../.venv/Scripts/python.exe generate_images.py     # regenerate the two diagrams (pure PIL, no API)
../.venv/Scripts/python.exe rag.py "your question" --top-k 3
```

## It works — verified with real, meaningful score gaps

Three test queries, checked directly against each image's raw cosine
similarity (not the final merged/normalized ranking — see the caveat
below):

| Query | status-ring-legend.png | hub-mesh-topology.png | Correct? |
|---|---|---|---|
| "What color does the status ring turn during a Hub 2 factory reset?" | **0.629** | 0.271 | ✅ legend wins by a wide margin |
| "How many devices are connected across the whole Hub Mesh...?" | 0.316 | **0.678** | ✅ topology wins by a wide margin |
| "What is the warranty policy for the Nimbus Battery Base?" (unrelated to either image) | 0.205 | 0.055 | ✅ both low — correctly recognized as irrelevant |

These are real, substantial gaps (0.63 vs 0.27; 0.68 vs 0.32), not noise —
the model is doing genuine visual+semantic matching, not returning
whichever image happens to be first. The Hub 2 factory reset color
(orange) exists **nowhere in this project's text corpus** (that fact only
appears in the image, and, separately, in project 08's `hub2-legacy-
notes.md`, which isn't part of this corpus) — this query can only be
answered correctly by actually retrieving and reading the image.

## Full retrieval result

```
../.venv/Scripts/python.exe rag.py "What color does the status ring turn during a Hub 2 factory reset?" --top-k 5
```
Real output — the image ranks #2, ahead of three text chunks about status
ring colors for *other* situations (which are topically close but don't
answer the Hub-2-specific question):
```
[1] TEXT   troubleshooting.md: "Status ring is flashing red..." (firmware failure, not factory reset)
[2] IMAGE  status-ring-legend.png
[3] TEXT   troubleshooting.md: "Status ring is solid red..." (Wi-Fi loss, not factory reset)
[4] TEXT   troubleshooting.md: "Factory reset. Hold the pairing button for 15 seconds... purple" (Hub 3's color, not Hub 2's)
[5] TEXT   installation-guide.md: "...status ring turns solid green" (connection, not reset)
```
Every text chunk here is topically adjacent (they're all about status
ring colors) but wrong for this specific question — [4] is even the
Hub-3-equivalent fact with the wrong color. Only the image has the
actual answer.

## A real caveat: text and image scores aren't on the same scale

Text is embedded with `voyage-3.5`; images are embedded with
`voyage-multimodal-3` — two different models, two embedding spaces with no
guaranteed shared geometry or score range. `rag.py` handles this with
min-max normalization (`normalize()`): rescale each modality's scores to
`[0, 1]` independently before merging. This is a real limitation, not
fully solved here: with only 2 images in the corpus, min-max normalization
trivially maps whichever one scores higher to exactly 1.0, *regardless of
its absolute relevance* — a mediocre image match could look like a
"perfect" 1.000 purely because it's the better of only two options. That's
why this README verifies retrieval against **raw, un-normalized** cosine
scores (the table above) rather than trusting the merged top-k ranking's
normalized numbers at face value. A real system with many images per
modality would see this problem shrink (min-max over a large, varied pool
is more informative) but wouldn't eliminate it — comparing scores across
different embedding models is inherently approximate. Calibrating this
properly (e.g. reciprocal rank fusion like 04, instead of raw score
normalization) is a reasonable next step if this became more than a demo.

## Why this needed its own project

Nothing about the retrieval math changed from 01 — it's still cosine
similarity over embeddings. What's new is that the corpus itself can't be
fully represented as text at all: a network topology diagram or a color
legend is genuinely more information-dense as an image than as a
paragraph describing it. Multimodal embedding lets that content join the
same retrieval pipeline instead of requiring someone to manually write a
caption (and keep it in sync with the image) before it's searchable at
all.
